# Монтажные чертежи обвязки кодом

Чертёж описывается программой: каждый узел — функция, которая рисует трубы, клампы, краны и подписи в миллиметрах. Это даёт то, чего нет при ручном черчении: одна и та же геометрия переиспользуется в детальном листе и в сборке; номера соединений и ведомость считаются сами; проверка находит разрывы линий и наложения подписей; а после любой правки весь комплект (SVG, PDF, Visio) пересобирается одной командой.

## Что в скилле
- `scripts/draw.py` — движок: класс `Sheet`, примитивы, символы арматуры, рамка со штампом, таблицы, вывод `to_svg` и `to_vsdx`. Справка по API — `references/api.md` (читай перед началом работы с движком).
- `scripts/place.py` — расстановка подписей ферул у номеров соединений в свободное место.
- `scripts/check.py` — автопроверка листов (`python3 check.py project.py`).
- `scripts/legend.py` — готовый лист «Условные обозначения» (`drawings_legend`).
- `scripts/export_pdf.js` — SVG-листы → один PDF + PNG-превью (Playwright/Chromium).
- `scripts/example_project.py` — рабочий пример: узел, ведомость соединений, сборка, чистовая сборка. **Начинай новый проект с копии этого файла** — в нём уже есть ведомость `J`/`JR`, сводка и экспорт.
- `assets/visio-template.vsdx` — шаблон для Visio.
- `references/drafting-rules.md` — правила оформления и инженерные правила обвязки (материалы прокладок и рукавов, запас при заказе, тройники, ёлочки) + уроки проекта ТЕФКОТ 770. Прочитай до того, как рисовать.
- `scripts/smeta_xlsx.py` — смета Excel из JSON: лист «По узлам схемы» + «Сводная к заказу» по поставщикам (`python3 smeta_xlsx.py data.json out.xlsx`). Пример данных — `scripts/examples/example_smeta-data.json` (группы по узлам + доп. лист «Аргоновая линия», статусы КУПИТЬ / УТОЧНИТЬ / ЕСТЬ / ЭТАП 2).
- `references/3d-model.md` + `scripts/render3d/shot3d.js` — 3D-модель установки в STEP/GLB (CadQuery, пример `scripts/examples/example_3d_model.py`, просмотрщик `assets/viewer.html`) и рендеры видов.
- **Эталонный проект** — папка `tefkot/` в этом репозитории: P&ID (`tools/scheme_vsdx.py`), монтажные чертежи (`tools/cherteg.py`), 3D (`tools/step_model.py`), смета, итоговый комплект в `itog/`. Подглядывай туда за готовыми решениями узлов.

## Порядок работы

1. **Собери исходные данные.** Аппараты и их штуцеры (размер ферулы!), что куда идёт, среды (растворитель? щёлочь? газ?), фото узлов, что уже есть на месте. Неизвестное не выдумывай — рисуй и помечай «?» (текст с «?» автоматически красный), а вопросы собери в список замеров.
2. **Скопируй пример** в папку проекта вместе с `draw.py`, `place.py`, `check.py`, `legend.py` и `assets/` (или добавь путь к `scripts/` в `sys.path`). Задай `draw.ORG`, `draw.PROJECT`, `CODE` (шифр), число листов.
3. **Нарисуй узлы функциями.** Один узел — одна функция с параметрами положения. Детальный лист вызывает её с `J` (создаёт соединения), сборка — с `JR` (ссылается на те же номера по тексту `where`). Так номера на сборке и деталях всегда совпадают.
4. **Каждое кламповое соединение — через `J(...)`** с размером, начинающимся с ферулы (`'K25'`, `'K50,5 (DN25)'`), прокладкой (`'PTFE'`/`'EPDM'`) и понятным описанием места («кран V-2 → рукав на P-1»). Ведомость и сводка хомутов/прокладок строятся из этих записей.
5. **Собери и проверь:** `python3 project.py out && python3 check.py project.py`. Доводи до «ИТОГО замечаний: 0»: подвинь подпись, поменяй `side` у номера, доведи трубу до края символа (кламп ±1.8 мм вдоль оси).
6. **Посмотри глазами.** Проверка не видит смысла: `node export_pdf.js out/all.pdf out/list-*.svg --png out/png`, открой PNG крупных узлов (или вырежи фрагмент через viewBox) и убедись, что схема читается — линии не идут сквозь краны, подписи стоят у своих элементов.
7. **Выдай комплект:** PDF всех листов, `.vsdx` (Visio, редактируемый), SVG. Если просят «только сборку» или «чистовой лист» — сделай отдельный лист сборки `clean=True`: без рамки, штампа, заголовков, перечней, примечаний, ссылок «(лист N)» и красных «?» (функция `clean_sheet` в примере). Номера соединений оставь — по ним работает ведомость и заказ; убери, только если попросят.

## Полный комплект на выдачу
P&ID (PDF+VSDX, RU и EN) → монтажная сборка A1 (PDF+VSDX) → полный комплект листов (PDF+VSDX) → 3D (STEP-zip, GLB, рендеры) → смета XLSX → всё в один zip. Перед выдачей: проверка чертежей 0 замечаний, `check_svg` 0, PNG просмотрены, grep по снятым позициям пуст во всех представлениях.

## Правки по замечаниям
Пользователь обычно присылает скриншот фрагмента с пометкой. Найди узел в коде по позиции/тексту, поправь геометрию в функции узла (а не только на одном листе — иначе сборка и детали разойдутся), пересобери, прогони проверку и покажи PNG-фрагмент «после». Если правка меняет состав (новый отвод, тройник, кран), обнови и ведомость (это произойдёт само через `J`), и смету/заказ, если они есть в проекте — количество хомутов и прокладок по ферулам меняется.

## Технологическая схема (P&ID) в Visio
Если схема уже есть как SVG (например, внутри HTML-документа), её можно перегнать в `Sheet`: распарсить `path/line/rect/circle/text` с масштабом в мм и вызвать `to_vsdx`. Для русской версии подставь словарь замен подписей. Шрифт и размеры подбирай так, чтобы лист влез в A3 с полями 8 мм.

## Чего избегать (на этом уже обжигались)
- Две линии, врезающиеся в одну точку без тройника. Любое ответвление — тройник, и на схеме он должен быть виден (на P&ID — маркер-квадратик).
- Линия, «висящая» в воздухе: каждый конец — на символе, аппарате, стрелке продолжения или с подписью «→ куда».
- Числа, которые никто не просил: уставки, температуры, чистота газа, «заземлено» — на монтажном чертеже это шум. Пиши только то, что нужно для сборки.
- Названия клампов не по феруле. Размер клампа называют по наружному диаметру ферулы: K25, K34, K50,5, K64, K91, K119 — так их ищут в каталоге.
